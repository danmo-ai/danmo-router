# 合规与可接受使用说明

本文说明 **danmo-router** 的 intended use、部署方义务与责任边界。内容参考了同类开源中转/网关项目（如 [New API 合规与可接受使用政策](https://docs.newapi.ai/zh/docs/legal/acceptable-use)、[New API README 合规提示](https://github.com/QuantumNous/new-api)）的常见写法，并结合本仓库 MIT 许可与「多协议转发 + 额度分发 Portal」的能力面做了适配。**本文不构成法律意见**；具体业务请咨询专业律师并阅读各上游最新服务条款。

## 项目定位

danmo-router 是**自托管**的多协议 LLM API 网关与用量管理组件，典型场景包括：

- 企业或团队**合法取得**的上游 API Key / 合约账号下的统一鉴权与路由
- 组织内用量统计、分组额度、令牌与兑换码（**不内置支付**）
- 开发、测试、私有化部署中的多模型接入与协议/方言转换

**默认面向**：自用、团队内部、企业私有化部署。对外向不特定公众提供「按量售卖模型能力」或 API 转售，属于部署方自行开展的运营行为，须单独满足监管与上游授权要求（见下文）。

## 合法授权要求

部署方与最终使用者在使用本软件接入任何上游时，须同时满足：

1. **凭据来源合法**：渠道中的 API Key、服务账号、企业合约、云厂商 IAM 等，须为部署方**本人/本组织合法拥有**，或已获上游**书面或条款允许**的授权；不得使用盗窃、撞库、共享泄露、灰色市场等来源的凭据。
2. **遵守上游服务条款**：包括但不限于 OpenAI、Anthropic、Google、Microsoft Azure、AWS、国内各模型厂商等的使用政策、速率限制、禁止转售/禁止自动化滥用等条款。协议转换、负载均衡、故障切换**不能**作为违反上游条款的理由。
3. **遵守适用法律法规**：网络安全、数据出境、个人信息保护、生成式 AI 治理、支付与税务等，以部署方所在司法辖区及用户所在地区为准。
4. **内容与安全**：不得利用本软件生成、传播违法有害内容，或规避上游/平台的内容安全机制。

## 使用边界与禁止用途

本软件提供转发、协议/方言转换、多租户额度与日志等能力，**仅应在合法授权范围内**使用。下列行为由部署方自行承担法律与合同风险，**不在本项目设计目标或维护者鼓励范围内**：

| 类别 | 说明 |
|------|------|
| **规避上游协议的中转/拆分** | 将**个人订阅、试用、教育优惠、违反「禁止转 API」条款的账号**池化后，通过本软件对外提供统一 API 或按量计费；用多协议转换、换模型名、聚合渠道等方式**掩盖**实际调用主体或违反上游「单一租户/禁止再分发」的约定。 |
| **未授权转售** | 在未取得上游及当地法律允许的情况下，将模型能力作为商品向第三方售卖（含「便宜 Key」「合租 Claude/GPT」等）。 |
| **滥用与攻击** | 批量注册、绕过限速、恶意爬取、攻击上游或本部署实例、未授权访问管理面或用户数据。 |
| **虚假或误导** | 对外宣称与官方等同的 SLA/合规资质，或使用不明来源 Key 导致模型身份、输出与标称不符却未告知用户（行业常见风险，见 [comparison.md](./comparison.md)）。 |

**允许且常见的合规用法**（仍需满足上游条款）示例：

- 公司采购的官方 API Key，给内部多个应用发**组织内**令牌，统一审计与计费分摊。
- 同一主体下多个**合规**企业账号做高可用与熔断，不对外转售额度。
- 在授权范围内做 OpenAI Chat ↔ Anthropic Messages 等协议转换，便于内部 SDK 统一，而非用于规避厂商禁止场景。

与 **Sub2API** 等「订阅账号转 API」类方案类似的风险：若上游明确禁止将订阅转为 programmatic API 或禁止共享，则即使用本软件部署，仍可能构成违约；维护者**不推荐**此类用途用于对外商业运营。

## 密钥、渠道与「聚合/opaque」渠道

- 管理后台配置的**上游 Key 由部署方负责**；本仓库示例数据中的 Key 均为占位符，不可用于生产。
- `opaque`（聚合）渠道仅表示上游规范未知时的**同协议透传**；**不**表示可合法接入任意第三方聚合商；是否允许使用该聚合商，由部署方与聚合商、上游之间的合同决定。
- 多 relay 副本、权重、优先级、熔断等，用于**高可用与流量调度**，不应被用于规避上游对单 Key 或单账号的公平使用限制。

## 面向公众提供生成式 AI 服务

若部署方通过用户 Portal 向**不特定公众**提供模型调用或生成式 AI 产品，须**自行**完成所在地要求的合规义务，例如（因地区而异，列举不全）：

- 算法备案、生成式 AI 服务备案或等效资质
- 内容安全审核、违法信息处置、用户协议与隐私政策
- 实名、未成年人保护、日志留存与安全评估
- 支付、发票、税务与消费者保护
- 对最终用户披露：服务由谁运营、数据如何处理、模型来源与限制

**本项目不提供上述合规能力的一揽子方案**；开源社区版亦**不**对部署方的经营合法性背书。
